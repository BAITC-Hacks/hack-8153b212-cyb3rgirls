# EventMatch — CYB3RGIRLS

Прототип для кейса #79-lite: до трёх event-подрядчиков с объяснениями по проверенным данным. Работает в браузере, без установки зависимостей и без API-ключей.

## Запуск

Самый простой способ: открыть `dist/index.html` двойным щелчком. Все файлы папки `dist` должны оставаться рядом.

Альтернатива при установленном Python: `python -m http.server 8000 --directory dist`, затем открыть `http://localhost:8000`.

Проверки при установленном Node.js: `node tests.cjs`.

## Данные

66 профилей из выданного `hackathon dataset anonymized .xlsx`. В `dist/data.js` списки с разделителем `|` преобразованы в массивы. Сохранены идентификаторы, описания, цены, календари и флаги происхождения. 13 профилей синтетические уже в исходном наборе. Команда не добавляла профили. Календарь ограничен 23.09.2026–31.12.2026. Данные статические, актуальная доступность в реальном мире не проверяется.

## Пайплайн

1. Проверка входных параметров и диапазона дат.
2. Отбор по городу и категории. Пустой каталог даёт отдельный исход `category_absent`.
3. Жёсткое исключение занятых, превышающих бюджет по стартовой цене, не принимающих формат, не соответствующих указанному языку или длительности. `max_hours = null` означает, что проверка времени присутствия неприменима.
4. Если кандидаты были, но все исключены, исход `no_match`. Иначе `matched`.
5. Порядок: явное упоминание формата в описании, затем стартовая цена по возрастанию, затем ID по возрастанию. Цена не считается оценкой качества. Правило простое и детерминированное; семантического поиска здесь пока нет.
6. До трёх карточек с фактами совпадения и цитатой из описания. Счётчики причин могут пересекаться, поэтому их сумма может быть больше числа исключённых профилей.

## AI: текущий статус

Генеративная модель в этой версии **не подключена**. Объяснения формируются локально из фактов и цитат. Это воспроизводимая базовая версия и резервный режим для последующей AI-интеграции.

Следующий этап: отдельный серверный обработчик, который получает только три отобранных профиля и проверенные факты; модель составляет 1–2 предложения с различиями между кандидатами. Сервер проверяет результат, ограничивает время запроса и при ошибке возвращает текущие объяснения. Модель не меняет состав или порядок карточек. Ключ хранится только в серверной переменной окружения, не в браузере и не в репозитории. Не вводить ключи в эту статическую версию.

## Сценарий демонстрации

Кнопки под формой выбирают запросы на основе самого набора данных:

- «Ведущие»: плотная категория с несколькими подходящими кандидатами.
- «Другая дата»: тот же заказ, другая дата и другой состав карточек; видны дата и число занятых.
- «Флористы»: редкая категория, подходящих меньше трёх.
- «Маленький бюджет»: категория есть, условий не проходит никто.
- «Нет категории»: в выбранном городе категория отсутствует.
- Повторить первый запрос и проверить неизменность порядка.

Цены показываются как «от», а не как окончательная смета. В интерфейсе отмечены синтетические профили, расчётные цены и города. Приложение не бронирует подрядчиков.

## Файлы

- `dist/index.html` — форма и структура страницы.
- `dist/style.css` — адаптивный интерфейс.
- `dist/data.js` — исходные профили в формате JavaScript.
- `dist/engine.js` — фильтры, ранжирование, фактические объяснения.
- `dist/app.js` — интерфейс и демонстрационные запросы.
- `tests.cjs` — проверки на настоящем наборе данных.

## Загрузка в пустой GitHub-репозиторий

1. Распаковать ZIP проекта.
2. Открыть репозиторий и выбрать «uploading an existing file» либо «Add file → Upload files».
3. Перетащить README.md, tests.cjs и папку dist целиком. Не загружать сам ZIP вместо исходников.
4. Написать сообщение `Add working EventMatch prototype` и нажать `Commit changes`.
5. Убедиться, что README отображается на главной странице, а в папке dist видны все пять файлов.

GitHub хранит код. Загрузка файлов сама по себе не публикует сайт. Для совместной работы команды далее лучше использовать отдельные ветки и pull requests.
