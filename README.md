# Mereke / Мереке — CYB3RGIRLS

Mereke помогает заказчику выбрать до трёх event-подрядчиков в Казахстане и понять различия между ними. Проект для кейса #79-lite: выбор из заданного каталога по условиям мероприятия.

## Что реализовано

- Город, дата, формат, категория, бюджет; необязательные язык, длительность и пожелания.
- Жёсткое исключение занятых и не соответствующих условиям подрядчиков.
- До трёх карточек в стабильном порядке с фактами, ценой «от» и цитатами из профиля.
- Различия между карточками: единственная минимальная стартовая цена, единственный максимальный лимит часов, языки, отсутствующие в остальных карточках. Метки появляются только когда сравнение подтверждено.
- «Пожелания»: совпадения слов и простых русских окончаний с описанием влияют только на порядок допустимых кандидатов.
- Три исхода: подобрали; категории нет в городе; кандидаты есть, но не проходят условия.
- Счётчики исключений; один профиль может иметь несколько причин, поэтому счётчики нельзя складывать как независимые группы.
- При изменении только даты — сравнение числа кандидатов и имён показанных подрядчиков, которые стали заняты или освободились.
- Шесть демонстрационных запросов, адаптивный интерфейс, отметки синтетических профилей и проставленных организаторами цен/городов.

## Сценарий пользователя

Заполнить параметры → при желании добавить пожелания → нажать «Подобрать подрядчиков» → сравнить условия, цитаты и различия. Если вариантов мало, посмотреть причины и вручную изменить условия. Сервис сам не увеличивает бюджет и не переносит дату.

## Технологии и AI

HTML5, CSS3, JavaScript. Для браузера не нужны зависимости, сборка, сервер и ключи. Проверки используют встроенные модули Node.js.

**Внешняя AI-модель и API пока не подключены.** Объяснения составляются из данных и цитат. Сопоставление пожеланий — локальная эвристика, а не семантическая модель. Интерфейс не выдаёт её за генеративный AI.

Следующий этап: серверный обработчик выбранного AI-провайдера. Он получает уже отобранные профили и проверенные факты, запрашивает короткие индивидуальные объяснения, проверяет результат и при ошибке/таймауте возвращает текущий резервный вариант. Модель не меняет доступность, цены, состав или порядок карточек. Ключи хранятся только на сервере в переменных окружения, не в браузере и не в GitHub.

## Архитектура и алгоритм

```text
Форма → проверка ввода → engine.js ← data.js
    → город и категория
    → занятость, бюджет, формат, язык, часы
    → ранжирование → до 3 карточек и причины исключения
    → факты, цитаты, сравнение → front.js → интерфейс
```

Порядок: больше совпадений с пожеланиями → явное упоминание формата в описании → меньшая стартовая цена → ID. Цена не является оценкой качества. Пожелания не исключают профиль, соответствующий обязательным условиям. При отсутствии совпадений интерфейс сообщает об этом. Из описания выбирается предложение с совпадающими пожеланиями и отличительными словами относительно других выбранных профилей.

## Установка и запуск

Самый простой способ: распаковать проект и дважды открыть **dist/index.html**. Все пять файлов в dist должны оставаться рядом. Нужен современный браузер.

При установленном Python, из папки проекта:

```sh
python -m http.server 8000 --directory dist
```

Открыть http://localhost:8000.

При установленном Node.js запустить проверки:

```sh
node tests.cjs
```

Проверки охватывают 204 сочетания города, категории и даты на исходном наборе, стабильность, занятость, бюджет, формат, язык, длительность, границы бюджета и неприменимость часов. Дополнительно проверяются сценарии из таблицы, пожелания, сохранение жёстких ограничений и правдивость сравнений.

## Как проверить: сценарии для жюри

Количество указано после фильтрации, до ограничения тремя карточками. Значения проверены на включённом наборе.

| Сценарий | Параметры | Ожидаемый результат |
|---|---|---|
| Плотная категория | Алматы, Ведущий, корпоратив, 15.10.2026, 1 000 000 ₸, русский, 6 ч | 6 допустимых кандидатов, показаны 3 |
| Другая дата | Тот же запрос на 16.10.2026 | 4 допустимых кандидата; состав меняется из-за календаря |
| Редкая категория | Алматы, Флорист, свадьба, 15.10.2026, 300 000 ₸, язык и часы не заданы | 2 карточки |
| Условия не подошли | Предыдущий запрос с бюджетом 100 000 ₸ | no_match, объяснение причин |
| Категории нет | Астана, Декоратор, свадьба, 15.10.2026, 300 000 ₸ | category_absent |
| Пожелания | Первый запрос + «импровизация и интерактивы» | Совпадающие слова учитываются в порядке и показаны в карточках |

Кнопки под формой воспроизводят запросы. Нажать первый, затем второй — появится сравнение дат. Повторить первый запрос — порядок должен совпасть.

## Данные и интеграции

Источник: выданный организаторами hackathon dataset anonymized .xlsx. Статическая копия — dist/data.js. Списки с разделителем | преобразованы в массивы. Сохранены все 66 профилей, идентификаторы, описания, календари и флаги. Новые профили команда не добавляла.

- 50 профилей — Алматы, 15 — Астана, 1 — «Зарубежье».
- 17 категорий; профиль может иметь несколько категорий.
- 13 синтетических профилей уже были в исходном наборе.
- Календарь: **23.09.2026–31.12.2026**; другие даты не принимаются.
- max_hours = null: время присутствия неприменимо, а не равно нулю.
- Цены «от» не гарантируют итоговую стоимость; price_imputed и city_imputed обозначены в карточках.

Приложение не отправляет данные AI-сервисам. Статические профили доступны пользователю браузера; для заданного анонимизированного учебного набора это ожидаемо.

## Ограничения

- AI API, эмбеддинги, свободный диалог, бронирование, заявки, портфолио и отзывы не реализованы.
- Пожелания не распознаются как полноценный смысловой запрос. Не поддерживаются все синонимы и сложные отрицания. Простые «без …»/«не …» ищутся буквально; совпадение слов не гарантирует исполнение пожелания.
- Календари учебные; свободная дата не является подтверждением реального подрядчика.
- Не выполняются обучение модели, поиск в интернете и добавление вымышленных характеристик.
- Изменение набора может изменить результаты демонстрационных запросов.

## GitHub и почасовой прогресс

Первая загрузка: открыть репозиторий → uploading an existing file → перетащить папку dist, README.md, tests.cjs и .gitignore → Commit changes. Загружать исходники, не ZIP вместо них.

Обновление через браузер: загрузить те же пути поверх существующих файлов; не создавать вложенную папку с ещё одной копией проекта. Сообщение коммита этой версии: **Apply teammate frontend and butter yellow Mereke theme**.

В уже клонированном репозитории и своей ветке:

```sh
git status
git add dist README.md tests.cjs .gitignore
git commit -m "Apply teammate frontend and butter yellow Mereke theme"
git push
```

Отправляйте реальные изменения примерно каждый час, как требуют организаторы; не создавайте фиктивную историю за прошлые часы. Разделите работу: интерфейс; подбор; AI и документация. Используйте отдельные ветки и Pull Request. Уточните, засчитываются ли любые ветки или только main. Не загружайте API-ключи.

## Обновление интерфейса: фронт команды и butter yellow

Основа: предоставленный участницей команды `smart_event_vendor_selector.html`. Сохранены структура шапки, центральный заголовок, широкая панель критериев, ползунок бюджета, пресеты, три карточки, просмотр полного профиля и избранное.

Название — Mereke. Основной butter yellow — #F4DF8A, светлая подложка — #FFF8DC, границы — #D7BD58. На жёлтом используется тёмный текст. CSS, значки и скрипты локальные: внешние CDN, шрифты и фотографии для запуска не требуются.

Демонстрационные долларовые цены и девять вымышленных профилей из макета заменены 66 профилями организаторов. Не используются придуманные рейтинги, отзывы, годы опыта, фотографии людей и фиктивные заявки. Полный профиль показывает исходное описание, языки, часы, форматы и флаги происхождения. Избранное хранится в localStorage, при невозможности сохранения — только до закрытия страницы; при смене условий доступность сохранённого профиля пересчитывается.

Проверены форма, два вида пустых результатов, полный профиль, добавление и удаление избранного, мобильная и широкая компоновка. Для быстрого просмотра отдельно предоставляется `Mereke.html`: тот же сайт со всеми стилями, логикой и данными внутри одного файла. В ZIP лежит разбитый на файлы проект для совместной разработки. После изменения исходников однофайловую копию нужно пересобрать.
